# 구현 분해의 진입점

화면을 파일 개수로 세지 않는다. **7개 내부 페이지 · 4개 표시 단계 · UI 18개 모듈 · 처리/환경/검증 계층 21개 모듈**로 책임을 나누었다. 실제 활성 UI 48개 TSX/CSS 파일을 연결하고 사용하지 않는 8개 파일은 기준에서 제외했다. 한 파일이 여러 책임을 갖거나 여러 파일이 한 모듈을 이루는 경우를 허용한다.

| 읽을 계약 | 내용 |
|---|---|
| [UI tree](ui-tree.md), [UI modules](ui-modules.json) | 페이지·컴포넌트·사용자 행동·모션·오류·빈 상태, 120개 질문 |
| [Core tree](core-tree.md), [Core modules](core-modules.json) | 입력·계약·자료 소유·판정·반복·외부 서비스·자원 효율, 123개 질문 |
| [질문별 추적표](../traceability.csv) | 전체 243개 질문 → 소유 명세·라이브러리·의존 모듈·현재 profile 제품 검증 gate |
| [독립 평가 절차](../reviews/current-reproduction/PROTOCOL.md) | 문서만 읽는 명확성 평가와 원본 대조 정확성 평가를 분리 |

이 숫자는 분해 및 설계 검토의 모집단이다. 테스트 실행 수나 제품의 모든 가능한 행동 수가 아니다. 각 질문 아래에 명세의 세부 상태표·공식·경계값·음성 사례가 있다. 구현자는 질문에 답할 문장이 없거나 명세 간 값이 다르면 임의로 추정하지 않고 이슈로 남긴다.

## 같은 페이지에서도 분리하는 책임

`STEP-05 검토`는 UI-07(작업 맥락), UI-08(실제 추출·판정 패킷), UI-09(진행·로그 관측), UI-10(인과 관계에 따른 전달 모션)으로 나뉜다. 실제 처리는 CORE-04/05/06/11/12/13/15가 담당한다. 빛이 이동했다는 이유로 판정·파일 처리 완료를 만들면 안 된다. 실제 이벤트의 actor·parent·document·handoff와 연결한다.

`STEP-06 결과`는 UI-12(파일별 결과), UI-13(즉시 근거·사람 수정), UI-14(전체 요약), UI-15/16/17(맞춤 대시보드 생성·차트·원문 연결), UI-18(내보내기)로 나뉜다. 차트 스타일은 바뀌어도 CORE-12의 판정 snapshot은 바뀌지 않는다.

## 작성과 검증

`node architecture/tools/build-traceability.mjs`는 두 registry에서 추적표를 생성한다. 질문 ID와 모듈을 임의로 삭제하지 않는다. 모집단을 정정하거나 보완할 때 변경 이유를 검토 이력에 남기고 새 해시를 독립 평가한다. 이 생성기는 통과 점수를 만들지 않는다.


과거 독립 재감사에서 203질문을 삭제하지 않고 32질문 및 CORE-20/21을 추가했다. 이번 재현 감사에서 235질문을 보존하고 8질문을 추가해 243질문이다. [현재 모집단 변경](../reviews/current-reproduction/population-changes.json), [211개 소스·설명 파일 역추적](source-trace.json), [현재 평가](../reviews/current-reproduction/README.md)를 참조한다. source snapshot의 210개 소스·설정에 server README 1개를 더 추적하는 차이다. 과거 main-session 평가 37모듈/203질문을 현재 결과로 재사용하지 않는다.
