## 모집단과 산식

최초 기존 모집단은 core 19 + UI 18 = 37모듈, 질문 203개다. 코드에서 발견한 기능·상태·분기·오류·상호작용 누락은 질문을 추가한다. 기존 질문은 삭제하거나 분모에서 제외하지 않는다. `population.json`에 추가 이유/출처와 전체 목록을 기록한다. 초기 원래 203질문 점수와 확장 모집단 점수를 모두 보존한다. 초기 시점에 새 질문의 반대 역할 평가가 없으면 UNVERIFIED다.

- 명확성 = 문서만으로 구현 계약을 결정할 수 있다고 독립 평가한 PASS 질문 수 / 선언된 전체 질문 수 × 100.
- 모호성 점수 = 100 − 명확성. 별도 심리측정 점수가 아닌 단순 보수다.
- 미해결 모호성 건수 = 명확성 FAIL + UNVERIFIED + 미검토 질문 수. 별도로 이슈 수와 중요도를 기록한다.
- 원본 정확성 = 소스 근거로 baseline 설명과 REQUIRED_REBUILD 구분이 옳다고 독립 평가한 PASS 질문 수 / 전체 질문 수 × 100. REQUIRED_REBUILD 문서가 명확하다는 것과 실제 구현됐다는 것은 다르다.
- 검토 포괄률 = 실제 PASS 또는 FAIL 의견이 있는 질문 수 / 전체 질문 수 × 100. UNVERIFIED/미검토는 제외한다.
- 소스 파일 추적률 = 역할·기능·대응 spec 또는 비실행/생성물 사유가 명시된 파일 수 / 비밀 제외 source snapshot 전체 파일 수 × 100. 이것은 파일 단위 범위이며 모든 실행 경로의 검증률이 아니다. 기능 역목록과 신규 질문 근거를 함께 제공한다.
- 모듈별 분모는 해당 모듈의 전체 질문 수, 단계별 분모는 해당 STEP에 연결된 질문의 중복 제거 집합이다. 한 질문이 여러 단계에 속하면 각 단계에 포함되지만 총합에는 한 번만 포함한다.

누락/중복/근거 없음/해시 불일치는 pass로 보정하지 않는다. 점수는 선언된 질문 범위의 설계 평가이며 임의 입력에 대한 보편적 완전성 증명이 아니다. 모든 질문 pass·열린 이슈0을 설계 완료 조건으로 쓰고, 확인 불가능한 요구는 숨기지 않는다.

## 보존·재검증·실행 경계

초기 결과와 initial-inputs는 수정 전 버전의 역사다. 현재 설계 변경 이후 과거 pass를 현재 점수로 재사용하지 않는다. 수정 회차마다 질문/이슈/수정 위치/다른 평가자의 판정과 해시를 새로 남긴다. 최종 평가는 current-inputs의 고정 설계에 대해 수행하며 역사·실행 출력·manifest 자신의 해시를 순환 참조하지 않는다.

이번 실제 작업은 문서·소스 대조와 오프라인 패키지/검증기/이식성 검사다. 실제 재구현, npm 새 설치·제품 build, 브라우저·모션 관찰, 실제 Gemini/E2B, golden/v3 전수 처리, sealed holdout은 실행하지 않는 한 `NOT_RUN`이다. 과거 screenshots 및 provider 기록의 존재를 이번 실행으로 세지 않는다. 앱 8791 또는 다른 작업의 서버/브라우저에 접근·중단하지 않는다.
