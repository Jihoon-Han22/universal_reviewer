# 설계 작업 에이전트 사용 기록

집계 시점: **2026-09-20T17:30:14.144Z**. 이후 호출은 포함하지 않은 동결 스냅샷이며, 최종 설계 합격 선언과는 별개다. [기계 판독 원장](agent-usage.json)에 개인별 ID·부모·호출 시각·역할과 해시가 있다.

## 현재 작업의 실제 인원

**고유 하위 에이전트 79개** = 직접 위임 15개 + 그 아래 보조 에이전트 64개. 이 대화의 총괄 설계 에이전트 **1개는 별도**다.

| 주 역할 | 고유 에이전트 |
|---|---:|
| 집계 | 1 |
| 설계 작성·수정 | 9 |
| 평가 | 54 |
| 모듈·기능 분석 | 10 |
| 검증·참조 화면 | 5 |

평가 54개는 **최종 평가 책임자 4개와 그 보조 50개**다. 독립 최종 평가표가 54개라는 뜻은 아니다. 한 에이전트가 분석과 수정 모두를 수행해도 주 역할 한 곳에만 센다. 예를 들어 두 분해 책임자는 분석에 집계하고 설계 수정 참여는 같은 ID의 후속 호출로 기록한다. 집계 에이전트 자신도 1개 포함했다.

## 회차별 신규·재사용

| 평가 회차 / 작업 구간 | 고유 참여 | 신규 | 재사용 | 후속 위임 호출 |
|---|---:|---:|---:|---:|
| R1 | 54 | 54 | 0 | 11 |
| R2 | 58 | 25 | 33 | 46 |

R1 구간은 최초 설계·분해·1차 평가와 그 피드백 수정을 포함한다. R2는 **2026-09-20T17:13:10.629Z**의 최초 재평가 지시부터 집계 시점까지다. 4개 평가 책임자에 대한 시작 호출은 원장에 각각 보존했다. R2 안에서 발견된 문제의 추가 수정·재검토는 R2의 하위 반복이며, 닫힌 3차 평가로 부풀리지 않는다. 같은 에이전트의 재실행은 신규 1개가 아니다. 각 회차의 고유 참여 수를 더하면 재사용 인원이 중복되므로 전체 고유 수와 다르다.

‘참여’는 해당 시간 구간의 생성 또는 assistant 응답·도구 호출 메타데이터가 확인된 경우다. 후속 위임은 tool call 개수이며 실제 새 실행 턴 수와 동일하다고 주장하지 않는다. 정확한 동시 실행 최고치는 스케줄러 전체 이력을 검증하지 않아 표시하지 않는다.

## 이전 작업과 제외 범위

- 영상 제작 작업은 제외했다.
- 이전 제품 구현·수정 에이전트도 제외했다.
- 중단·보관한 이전 설계 작업은 현재 집계에 합치지 않았다. 전체 원장이 없어 **총 사용 인원은 확인 불가**다. 로컬에서 보이는 하위 기록은 2개뿐이며 전체 수로 사용하지 않는다. 인계 당시 ‘실행 중 7개 중단’은 활동 상태에 대한 보고이지 누적 인원 수가 아니다.

## 감사 방법과 제한

세션 첫 줄의 식별자·부모·경로·시각, 선택한 collaboration 도구의 이름·대상·call ID·시각만 집계했다. 암호화된 메시지 내용을 해석하거나 복사하지 않았고 .env 또는 API 키를 읽지 않았다. 역할은 실제 위임 소유권을 기준으로 분류했으며 개인별 기록에 분류 근거를 명시했다. 메타데이터 투영 및 호출 목록 SHA-256은 JSON에 있다. 원본 세션 파일은 작성 이력 감사 자료이며 재구현에 필요한 실행 의존성이 아니다.

이 집계는 **사용량·역할의 추적 기록**이다. ‘모호성 0·명확성 100’ 달성 여부는 각 회차의 평가표와 score.mjs 결과로 별도 증명해야 한다.
