# 설계 검토 모집단과 수정 이력

## Round 01 — 실제 발견 사항

2026-09-21, 기존 초안에 대해 작성자와 별도인 4명의 평가자가 분리 검토했다. 명확성 평가자는 architecture만 읽었고 정확성 평가자는 원본과 비교했다. 아래는 당시 문서 해시에 대한 역사적 결과다. 수정된 문서의 점수로 재사용하지 않는다.

| 범위 | 통과 | 실패 | 미검증 | 열린 지적 |
|---|---:|---:|---:|---:|
| Core 명확성 | 64 | 26 | 0 | 22 |
| Core 정확성 | 68 | 15 | 7 | 23 |
| UI 명확성 | 62 | 45 | 1 | 34 |
| UI 정확성 | 64 | 44 | 0 | 47 |

총 질문은 198개이며 각 질문을 명확성·정확성 두 번 평가한다. 같은 원인을 두 평가자가 지적할 수 있으므로 지적 수 126을 서로 다른 결함 126개라고 해석하지 않는다. [R1 보고서](round-01/)에는 질문별 근거·문서 해시·미해결 사유가 보존된다.

## 모집단 정정: CORE-14-C05

R1 질문은 iframe 메시지에 runId 검사를 요구했지만 실제 wire 계약은 `source window + opaque origin(null) + channel + type + preview token + itemId 허용 목록`이다. runId는 호스트의 작업/cache 범위다. R2 질문은 실제 브리지 필드를 명시하도록 정정한다. 검증 대상 보안 경계를 제거하지 않으며 source/window/token/항목 교차 오염과 원본 파일 다운로드 제외를 계속 검사한다. 근거: R1-CORE 정확성 보고서, CORE-14-C05; 소유 명세 05 D07.

## 사용자 요구로 추가된 세밀도

자료구조·알고리즘·비동기 처리의 정확한 소유권·인덱스·복잡도·동시성·취소·메모리 제한을 [07 보충 계약](../../specs/07-data-algorithms-concurrency.md)으로 연결한다. **CORE-19와 5개 질문을 추가하여 37개 모듈/203개 질문**으로 확대했다. 기존 실패 질문은 삭제하지 않았다. 각 모듈의 읽을 문서 목록도 확장했다. 시각 재현은 최종 CSS cascade, JSX 시각 primitive, 폰트, 상태별 DOM 및 PNG를 같이 사용한다. 추가 계약도 R2에서 문서만으로 이해되는지와 원본과 일치하는지를 다시 검토한다.

각 작성자의 `fixes-*.md`는 R1 지적 → 수정 위치를 기록한다. 작성자가 ‘해결’이라고 적은 것만으로 인수하지 않으며 독립 R2가 판정한다. 추가된 파일의 해시를 포함해 다시 봉인한다.
